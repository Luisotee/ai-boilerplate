# Envios programados (`/admin/scheduled-sends`, FleetView-driven)

Loaded when working in `scheduled_sends/`. Also relevant to `routes/scheduled_sends.py`, `streams/scheduled_send_scheduler.py`, the per-send parts of `streams/broadcast_consumer.py` and `routes/broadcasts.py`, `/broadcast <number>` in `commands.py` and the `settings` tool's `scheduled_send_number`. Ported from castanha-bot PR #46 without regions or the weekly recap. Not the chat-created scheduled tasks (`services/CLAUDE.md`, `docs/scheduled-tasks.md`).

An operator schedules a **fixed text** or a **prompt for the agent**, once or recurring, to an audience. Every run is delivered as an ordinary **broadcast** (`services/CLAUDE.md` "Broadcasts"), so pacing, the shared 24 h Baileys cap, the send window, the Redis lease, the claims and the `unknown` rule are the broadcast consumer's, unchanged.

- **Tables** (all new, `create_all()`, no migration SQL): `scheduled_sends` (the send; `number` is the stable `/broadcast off <number>` code, `max+1` under an advisory lock on Postgres; rows are cancelled, never deleted), `scheduled_send_runs` (`UNIQUE(scheduled_send_id, scheduled_for)`; `broadcast_id` unique), `scheduled_send_run_texts` (what each agent run wrote), `broadcast_recipient_texts` (a recipient's own text), `scheduled_send_opt_outs` (PK send + `users.id`; `/clean` keeps the row, and `/link` merges move it to the kept row, so it never re-subscribes). JSON columns are `JSON` with a JSONB variant, so the SQLite tests can create them.
- **Schedule** (`schedule.py`, pure): `{kind: once|daily|weekly|monthly, run_at | time, weekdays (cron 0 = Sunday), day_of_month 1-28}` compiles to `run_at` / `cron_expr` fired by `services/schedule.next_fire` in the zone snapshotted at create/edit (`bot_timezone()`). Resume, and a PATCH that changes the schedule or status, recompute `next_run_at` from now (no catch-up); any other PATCH keeps the armed slot. `PATCH {"content": null}` is a 422.
- **Firing** (`runner.fire_due`, stream-worker task every 30 s): due `active` rows `FOR UPDATE SKIP LOCKED`; the slot's run and the advanced `next_run_at` commit together. Later than `catchup_window(period)` → run `missed`, next slot is the first after now (no burst). A one-shot ends `finished`. "Send now" (`POST /{id}/run`) is a `manual` run for the current minute, 409 while another run is preparing or its broadcast is live.
- **Preparing** (`runner.prepare_run`, up to 2 in parallel): claim by conditional UPDATE on `claimed_at` (stale after 60 min; a run preparing for 2 h is `failed/expired`). On shutdown (`CancelledError`) `safe_prepare` gives the claim back (`release_claim`, conditional on the token). Snapshot = `planning.plan_send` = `services/broadcast.plan_broadcast` (one message per person, whitelist per route with groups listed themselves, Cloud 23 h window, `unknown_client`, global opt-out) plus this send's opt-outs. Platforms are `baileys|cloud|telegram`; omitted = every reachable client; an explicit unreachable one keeps its recipients (the lane waits, then pauses on `client_disconnected`). No reachable client → run `failed/clients_unreachable`.
- **No regions**: the template has none. `regions` is always null; a non-empty one is a 422 (create, PATCH, preview); the list answers `regions: []` and `region_filter: false` (additive; castanha answers true); run texts and the preview sample have `region: null`.
- **Prompt runs** (`agent_run.generate_text`): **once per chat type** (group, private) in the audience, never per chat. Isolated like a scheduled task's agent run: `AgentDeps(scheduled_run=True)` (only `SCHEDULED_RUN_TOOLS`, read-only), a placeholder `user_id` (no core memory, writes nothing), a synthetic JID, no history, `is_group_admin=None`. `FIXED_RULES` (code, English) wrap the operator's prompt (≤ 2000 chars); `[SILENT]` as the whole output = send nothing; a text over 3000 chars gets one rewrite. Timeout `RUN_TIMEOUT_SECONDS` (180 s). A failed slice skips only its chats (`generation_failed`); all failing → run `failed`, nothing sent, no automatic retry.
- **Hand-over** (`runner.hand_over`): broadcast (`queued`, footer = `broadcast_footer` + `scheduled_send_footer` with `{number}`), recipients, their own texts and the run texts are inserted in **one transaction** with `UPDATE scheduled_send_runs SET status='delivering', broadcast_id=… WHERE status='preparing' AND claimed_at=:mine` (rowcount-checked) after re-reading the send `FOR UPDATE` (not `cancelled`): a concurrent cancel either lands first (run `cancelled`) or waits for the commit (run delivering; cancel it via its broadcast). So a run makes one broadcast at most. Zero pending recipients → `completed/no_recipients`, no broadcast.
- **Delivery changes in the broadcast pipeline**: `_next_recipient` re-checks the send's opt-outs (`opted_out_campaign`) and returns the recipient's own text rendered with the broadcast footer; history saves what was sent. `_ensure_none_active` ignores run broadcasts: they **queue FIFO** behind whatever is sending, and a manual broadcast queues behind them (no priority); resuming a run broadcast skips the check.
- **Opt-out**: global `/broadcast off` stops announcements **and** every send. Per send: `/broadcast off|on <number>` (only an ASCII-digit third token is a number; anything else, e.g. a trailing @mention, runs the global switch; a `finished` send answers that it ended; same group-admin gate, fail closed), the `settings` tool (`announcements` + `scheduled_send_number`), the footer. Bare `/broadcast` lists active/paused recurring sends whose audience can include this chat (`opt_out.can_reach`), with this chat's state.
- **Routes** (closed enums in `schemas.py`: `ScheduledSendContentType`, `ScheduledSendAudience`, `ScheduledSendStatus`, `ScheduledSendScheduleKind`, `ScheduledSendRunStatus`, `ScheduledSendRunTrigger`): `GET ""` (+ `weekly_recap`: FleetView requires it and the template has no weekly recap, so it is a fixed disabled summary; `regions`, `region_filter`, `timezone`), `POST ""` (idempotency key: 200 replay, 422 for a different body), `GET|PATCH /{id}`, `POST /{id}/pause|resume|cancel|run`, `GET /{id}/runs`, `GET /runs/{run_id}` (with texts, rate-limit exempt), `POST /preview` (counts, `estimated_agent_runs`, `next_runs`, `warnings`: `cloud_recurring`, `exceeds_period`, `exceeds_daily_cap`; `generate` runs the agent once). A `delivering` run's status is derived from its broadcast (`completed`/`cancelled`); pause/resume/cancel/recipients of a delivery are `/admin/broadcasts/{broadcast_id}/…`. Broadcasts gain `scheduled_send_id` / `scheduled_send_run_id`.
- **Tests**: `tests/integration/test_scheduled_sends_db.py` (SQLite, real constraints, routes, commands), `tests/unit/test_scheduled_send_schedule.py`.
