# Migrations

Hand-written, idempotent SQL for column and index changes, because `create_all()` never adds columns. The rule and the apply command are in the root `CLAUDE.md` / `AGENTS.md`.

Run it in the checkout: `docker compose exec` targets this checkout's own `postgres` whatever `SERVICE_NAME` is, so on a host with several bots it can't hit another bot's database. Substitute your `POSTGRES_USER` / `POSTGRES_DB` if you changed the defaults. Current migrations: `2026-09-21-kb-file-hash.sql`, `2026-09-25-broadcast.sql` (`users.broadcast_opt_out`, `last_client_id`, `whatsapp_client_id`, `cloud_last_inbound_at`, and `broadcast_recipients.attempt_started_at`, added later, so a DB that applied an earlier version must apply it again; the `broadcasts`/`broadcast_recipients` tables come from `create_all()`). `2026-11-09-core-memory-previous.sql` (`core_memories.previous_content` and `content_trusted`, for `/memories undo`). `2026-11-09-message-id.sql` (`conversation_messages.whatsapp_message_id` + index, for `/chat/revoke` and `/chat/edit`). `2026-11-09-vector-hnsw-indexes.sql` (HNSW indexes on `embedding::halfvec(3072)` for KB chunks and conversation messages; needs pgvector >= 0.8; uses `CREATE INDEX CONCURRENTLY`, which can't run inside a transaction, so apply it with plain `psql < file`, never `-1`/`--single-transaction` or a migration runner that wraps files in a transaction). `2026-11-09-kb-hybrid-search.sql` (the `unaccent` extension, the `kb_stem`/`kb_fold` text-search configs, `knowledge_base_chunks.content_tsv` + GIN index and `embedding_format`; set `-v kb_text_search_language=<lang>` when `KB_TEXT_SEARCH_LANGUAGE` isn't portuguese; order and re-embedding: `media-and-kb.md`). The `scheduled_tasks` and `task_runs` tables (and their indexes, including `task_runs.message`, `scheduled_tasks.created_by_jid` and `ix_task_runs_open`) come from `create_all()`, with no SQL file: that holds only because both tables are new in the release that added those columns. A later column or index on them needs a migration file like any other.
